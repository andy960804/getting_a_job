# Skill: 경력기술서 작성

## 트리거
경험 카드(db/experiences/)가 존재하는 상태에서 경력기술서 항목 작성 요청 시 이 스킬을 실행한다.

---

## 템플릿 (출력 포맷 고정)
```
프로젝트명 / 업무명

기간   : YYYY.MM ~ YYYY.MM (N개월)
성과   : [행동] + 으로/통해 + [결과 수치]
역할
- [행동(수치)] + 으로/하여/바탕으로 + [결과 수치]
- ...
기술   : tech #1 (도구 / 분석기법 / 구체적 스킬)
         tech #2 (프로세스 이해 / 법적요건 / 제도 이해)
```

---

## 섹션별 작성 규칙

### 기간
- 형식 고정: `YYYY.MM ~ YYYY.MM (N개월)`
- 진행 중인 프로젝트 사용 금지 — 성과가 확정된 경우에만 사용
- 기간이 과도하게 길면 성과가 발생한 구간으로 좁혀 기재

### 성과 (1줄 압축 공식)
```
[행동] + 으로/통해 + [결과 수치]
```
- 행동 1개 + 결과 1개 (같은 방향의 결과는 2개까지 허용)
- 비전문가도 읽으면 인과관계가 납득되어야 함
- 배경·맥락 없이 행동으로 바로 시작
- `→` 전후 비교에만 허용 (예: `40% → 1%`)
- 괄호 `( )` 사용 금지

| 예시 | 판정 |
|------|------|
| 신규 브랜드 런칭 | ❌ 수치 없음 |
| 100만원 달성 | ❌ 행동 없음 |
| 공급 방식 개선 및 PWM 자동화 라인 증설로 연간 CAPA 480만 개 확보, 공급 불량 100% 개선 | ✅ |

### 역할 (반복 항목 공식)
```
[행동(수치)] + 으로/하여/바탕으로 + [결과 수치]
```
- 중요도 순 배치 — 임팩트 큰 항목 먼저
- 인사이트가 2개 이상이면 항목 분리 (서로 다른 도메인 기여 → 별도 줄)
- `→` 전후 비교에만 허용
- 괄호 `( )` 사용 금지
- 쉼표로 3개 이상 나열 금지

| 예시 | 판정 |
|------|------|
| 데이터 수집 및 분석 진행 | ❌ 수치 없는 당연한 업무 나열 |
| 전압 드랍 검사 데이터 전수 분석으로 오검출 원인 및 1.34배 임계값 특정 | ✅ |

### 기술 (2줄 구조 고정)
- 1줄: 실제 사용한 도구 / 분석기법 / 구체적 스킬
- 2줄: 프로세스 이해 / 법적요건 / 제도 이해
- **tech #2가 숫자로 시작하면 파서 오류** → 반드시 한국어 명사로 시작
- 실제 사용하지 않은 도구·스킬 기재 금지

```
기술   : Python / CSV 검사 데이터 분석 / 전기 계측
         검사 설비 소프트웨어 변경 프로세스 이해
```

## 어휘 변환표 (구어체 → 비즈니스 한자어)

| 구어체 | 변환 |
|--------|------|
| 꾸준히 | 지속적으로 |
| 꾸준 달성 | 안정적 달성 |
| 꾸준 유지 | 지속 유지 |
| 착착 | 순차적으로 |
| 빠르게 | 신속히 |
| 제대로 | 적절히 / 체계적으로 |

## 경험 카드 → 경력기술서 매핑

| 경험 카드 필드 | 경력기술서 섹션 |
|----------------|----------------|
| 메타.기간 | 기간 |
| P1 Product + P3 Price (수치) | 성과 |
| P2 Place + P4 Promotion (행동) | 역할 항목 |
| C2 Company (도전과제) | 역할 항목 컨텍스트 |
| 메타.태그 (도구·스킬) | 기술 |

## 셀프 게이트 (출력 전 체크)

- [ ] 성과: 행동 1개 + 결과 수치 존재
- [ ] 성과: 괄호 `( )` 없음
- [ ] 역할: 각 항목 수치 존재
- [ ] 역할: 중요도 순 배치
- [ ] 역할: 인사이트 2개 이상이면 항목 분리
- [ ] 기술 2줄: tech #2가 한국어 명사로 시작
- [ ] 구어체 → 비즈니스 한자어 변환 완료
- [ ] `→` 전후 비교 외 사용 없음
