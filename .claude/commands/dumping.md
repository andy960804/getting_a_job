# Experience Dumping — Archivist 워크플로우

> 이 명령은 **Opus 4.6** 모델 전용입니다. 프로젝트 설정(.claude/settings.json)에 의해 자동 적용됩니다.

## 실행 순서

### STEP 1 — 경험 원재료 수집
사용자가 경험을 자유롭게 덤핑하도록 유도한다. 다음 질문으로 시작:

```
어떤 경험을 정리할까요?
프로젝트명, 기간, 본인이 한 일을 자유롭게 말씀해주세요.
수치가 없어도 괜찮습니다. 있는 그대로 덤핑해주세요.
```

### STEP 2 — 3C4P 인터뷰 (레이어별 드릴다운)
`rules/skills/archivist/card_format.md` 로드 후 7레이어를 순서대로 채운다.

미답 레이어가 있으면 질문을 이어간다:
- **C1** 빈 경우: "이 경험의 최종 수혜자(고객/사용자)는 누구였나요?"
- **C3** 빈 경우: "비슷한 사례나 참고한 방법이 있었나요? 없으면 '없음'으로 처리합니다."
- **P3** 빈 경우: KPI 전환 질문 7개 소진 (Archivist Hard Constraint GATE 2)

### STEP 3 — 수치 없는 항목 처리
수치가 없는 역할·성과는 다음 KPI 전환 질문 순서로 소진:
1. 이 일을 하기 전과 후에 무엇이 달라졌나요?
2. 몇 명에게, 얼마나 자주 영향을 미쳤나요?
3. 시간·비용 기준으로 얼마나 줄었거나 늘었나요?
4. 이 결과를 달성하는 데 얼마나 걸렸나요?
5. 같은 일을 팀 전체가 했다면 몇 배의 시간이 걸렸을까요?
6. 성공/실패 판단 기준이 있었다면 무엇인가요?
7. 상사 또는 고객의 피드백이 있었나요? 어떤 반응이었나요?

7개 소진 후에도 수치 없으면 → B급으로 저장.

### STEP 4 — 경력기술서 초안 병행 작성
`rules/skills/ghostwriter/career_description.md` 로드 후 경험 카드 데이터를 템플릿에 매핑:

| 경험 카드 | 경력기술서 |
|-----------|-----------|
| 메타.기간 | 기간 |
| P1 + P3 수치 | 성과 |
| P2 + P4 행동 | 역할 항목 |
| 메타.태그 도구 | 기술 |

### STEP 5 — 게이트 검사 (저장 전 의무)
`rules/skills/archivist/3c4p_linter.md` 실행:
- [ ] GATE 1: 3C4P 7레이어 모두 채워짐
- [ ] GATE 2: P3 KPI 수치 존재 (또는 질문 7개 소진 후 B급 판정)
- [ ] 경력기술서 셀프 게이트 15항 통과

### STEP 6 — 파일 저장
- 경험 카드: `db/experiences/YYYYMMDD_경험명.md`
- `db/experience_db.md` 인덱스 업데이트
- 경력기술서 초안 필요 시: `db/drafts/경험명_경력기술서_v1.md`

## Hard Constraints (Archivist 상속)
- 지어낸 경험 감지 시 즉시 중단
- tracker.tsv 회사+직무 중복이면 경고 후 확인 요청
- 7레이어 중 하나라도 비면 저장 금지
